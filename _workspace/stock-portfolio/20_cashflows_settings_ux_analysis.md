# 20. 입출금 · 설정(알림) 탭 UX 분석과 개선

작성일: 2026-08-10 · 대상: `입출금`(`src/react/views/CashflowsView.jsx`), `성과`(`PerformanceView.jsx`), `설정`(`AutomationView.jsx`)

## 배경

"입출금·설정 탭이 필요한지, 잘 쓰이는지 모르겠다. 설정 알림이 불친절하고, 입출금은 데이터가 하나도 안 보인다. 특히 배당."
→ 코드를 끝까지 따라가 실제 동작과 겉보기의 괴리를 진단하고 개선했다.

## 진단

### 입출금 — 필요하지만 절반이 죽어 있었음
- `portfolio-core.js`의 `getExternalFlowAmount()`는 **`deposit`(+)·`withdrawal`(−)만** 계산에 반영한다. **`dividend`·`tax`·`fee`는 `return 0`** — 기록돼도 성과 숫자에 영향이 없다.
- 즉 유형 5개 중 **세금·수수료는 어디에도 쓰이지 않는 dead input**이었고, 배당은 별도 "배당 인컴" 차트에만 그려졌다.
- 반면 입출금 자체는 **꼭 필요**하다. 성과 탭의 `투자손익 = 총자산 증감 − 입출금`이라서, 입금을 기록하지 않으면 **납입금이 전부 수익으로 잡혀 투자손익이 부풀려진다.**
- 데이터가 비는 이유: **전부 수동 입력 전용**. 보유 종목/계좌에서 자동으로 끌어오는 게 없어, 직접 넣지 않으면 영원히 빈 화면.

### 배당 — 보유 종목과 완전히 단절
- 배당은 holdings와 연결이 전혀 없어 **자동 인식 0**. 배당주(SCHD 등)를 보유해도 "🌱 배당 기록이 없습니다"만 뜬다.
- 배당은 성과(투자손익)엔 미반영이다. 이는 **회계적으로는 맞다**(배당이 계좌에 남아 재투자되면 이미 총자산 증가에 반영됨 → 중복 계상 방지). 다만 "내 수익 중 배당이 얼마"인지 보려면 배당 인컴 차트가 유일한데, 그게 수동 입력이라 사실상 안 쓰였다.

### 설정(알림) — 기능 과밀 + 불친절
- 한 탭에 알림 + 자동 기록 + 백업/복원 + 엑셀 가져오기 + 검증 리포트 + 초기화 + 로그 2종이 모두 있음.
- 알림 불친절 요인: ① 비로그인 시 통째 잠김 ② 텔레그램 전용 ③ `chat id` 요구인데 봇(`@stocklio_alarm_bot`)에 `/start`부터 보내야 한다는 전제가 화면에 없음 ④ "알림 기준"(large_move_threshold) 뜻이 placeholder만으로 불명확.

## 개선 내용

| # | 개선 | 대응 |
|---|---|---|
| 1 | 입출금 입력 유형에서 **세금·수수료 제거**(`INPUT_FLOW_TYPES` = 입금/출금/배당). 레거시 tax·fee 기록은 `FLOW_TYPE_LABELS`로 라벨만 표시 | dead input |
| 2 | **배당 빠른 입력** — 보유 종목의 (계좌·티커) 조합을 칩으로 노출. 칩 클릭 시 입력 양식이 배당·계좌·메모(`{종목명} 배당`)로 자동 채워짐 | 배당 수동 입력 진입장벽 |
| 3 | 배당 힌트 명시: "배당은 인컴 차트에만 집계되며 투자손익에는 중복 반영되지 않아요" + 빈 상태 안내를 빠른 입력으로 유도 | 배당-성과 관계 혼란 |
| 4 | 성과 탭에 **입출금 미기록 경고 배너**(스냅샷은 있는데 입금·출금 기록이 0일 때만): "투자손익이 부풀려질 수 있어요" | 투자손익 왜곡 |
| 5 | 알림 온보딩 **3단계 가이드**(봇 `/start` → chat id 찾기 → 사용/저장/테스트), 라벨/도움말 재작성("텔레그램 chat id", "큰 변동 알림 기준(원) · 0이면 매일"), 비로그인 안내 문구 개선 | 알림 불친절 |
| 6 | 입출금 탭 부제 "입금 · 출금 · 배당 기록"으로 수정(수수료 제거) | 일관성 |

### 의도적으로 하지 않은 것
- `getExternalFlowAmount`에서 배당을 P&L에 더하지 **않음** — 재투자 배당의 중복 계상을 막기 위함(위 진단 참고). 도메인 함수와 기존 테스트(`dividend→0`, `fee→0`)는 그대로 유지.
- 배당 "자동 추정"은 배당수익률 데이터 소스가 없어(Yahoo 프록시는 가격만) 보류. 대신 **빠른 입력**으로 수동 기록 비용을 최소화하는 방향 선택.

## 검증
- `npm run check`(도메인 34 pass) + `vite build` 통과.
- 로컬 브라우저: 유형 3개, 칩=티커(SPY·QQQ·SCHD…), 칩 클릭 시 양식 자동 채움(type=dividend·accountKey·note), 성과 배너는 샘플(입금 존재)에서 숨김=정상, 설정 비로그인 개선 문구 표시. 라이트/다크 확인, 콘솔 런타임 에러 0(잔존 에러는 기존 CSP 폰트/404뿐).
